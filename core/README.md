# Citizen core

The pet. One C99 translation unit set, no libc at runtime, no malloc, one static instance. The host owns time, input and storage; the core owns the pet and the pixels. It renders into a static 240x240 framebuffer of 8-bit palette indices (57,600 bytes) and the host converts that to RGB565 on the way to the panel.

The same six files build three ways: native with clang for the tests, wasm32 freestanding for the browser simulator in `sim/`, and riscv for the ESP32-C3 firmware in `firmware/`. Nothing in here knows which one it is running on.

Facts in this document come from `citizen.h`, `citizen.c`, `screens.c`, `gfx.c` and the output of `make test`, `make bench` and `make soak` on 16 Oct 2026. Every screen is pictured in the [screen gallery](../docs/screens/README.md).

## Layers

```
  host (firmware/src/main.cpp, sim/, tests/)
  time, touch, storage, WiFi, backlight, SPI push
        |  cz_tick / cz_touch / cz_set_* / cz_message / cz_checkin
        v
 +-------------------------------------------------------------+
 | citizen.c   state machine: hearts, timers, gestures, screens |
 |             save blob, Settings wheel, view key + clip rects  |
 +-------------------------------------------------------------+
        |  struct cz_view              ^ cz_anim, cz_anim_box
        v                              |
 +-------------------------------------------------------------+
 | screens.c   one function per screen, skyline, banner, QR    |
 +-------------------------------------------------------------+
        |  cz_rect / cz_blit / cz_text / cz_icon / cz_dim / cz_clip
        v
 +-------------------------------------------------------------+
 | gfx.c       palette, 3x5 font, 8x8 icons, clipped fills,    |
 |             dirty row span, stat counters                   |
 +-------------------------------------------------------------+
        |  cz_fb[240*240] palette indices
        v
  host reads cz_framebuffer() + cz_palette(), pushes cz_dirty_rows()

 sprites.c    3 creatures x 8 poses x 64x64, generated by tools/pack_sprites.py
 qrcodegen.c  Nayuki's QR encoder, used by the QR screen
 libc_shim.c  memset/memcpy for the wasm build only (CZ_FREESTANDING)
```

## Public API

Everything the host may call is in `citizen.h`, all prefixed `cz_`. The Makefile exports exactly this list to wasm. `now_ms` is the host's monotonic clock in milliseconds; it may wrap.

### Lifecycle

| Signature | What it does |
|---|---|
| `void cz_init(uint32_t seed, const uint8_t *saved, int saved_len, uint32_t slept_seconds)` | Resets the one instance. With a valid save blob the pet resumes and `slept_seconds` of wall-clock time are applied to hunger, play and the clock (capped at 7 days for the timers, exact modulo a day for the clock). With no blob or a bad one, `seed % 3` picks the creature, hearts start at 3, play is available at once and the screen is Hatch. |
| `int cz_save(uint8_t *out, int cap)` | Writes the 64-byte save blob. Returns `CZ_SAVE_SIZE` (64), or 0 if `out` is NULL or `cap` is too small. |

### Time and input

| Signature | What it does |
|---|---|
| `void cz_tick(uint32_t now_ms)` | Advances timers, hearts, screen timeouts, the hold gesture and the pending Settings tap. Call it every 16 to 50 ms. Rendering happens lazily when the host reads the framebuffer, not here. |
| `void cz_touch(int kind, int x, int y, uint32_t now_ms)` | Raw touch: `CZ_TOUCH_DOWN`, `CZ_TOUCH_MOVE` or `CZ_TOUCH_UP` at panel coordinates. The core detects tap, double tap, swipe and hold itself. Also advances time like `cz_tick`. Ignored in portrait mode. |

### Content the host sets

| Signature | What it does |
|---|---|
| `void cz_set_creature(int creature)` | 0 tapir, 1 hornbill, 2 tiger. Resets the name to the creature's default (TENUK, KENYALANG, HARIMAU); call `cz_set_name` after it for a custom name. Out-of-range values are ignored. |
| `void cz_set_portrait(int on)` | Web portrait: hatched, 4 hearts, Home with no hearts or action icons, touch ignored, never sleeps. |
| `void cz_set_name(const char *name)` | Up to 10 bytes, shown in gold under the pet. Not uppercased by the core; the font draws lowercase as uppercase. |
| `void cz_set_prompt(const char *prompt)` | Up to 96 bytes, typed out on Hatch at 60 ms per character. |
| `void cz_set_qr_url(const char *url)` | Up to 128 bytes, encoded on the QR screen. Default is the deployed site plus `/c/<lowercase name>`. |
| `void cz_message(const char *text)` | Up to 64 bytes. Opens Talk for 8 s from any screen except Hatch. |
| `void cz_checkin(const char *city)` | Up to 16 bytes. Opens Check-in for 4 s from any screen except Hatch. |

### Output

| Signature | What it does |
|---|---|
| `const uint8_t *cz_framebuffer(void)` | Renders if anything changed, then returns the 240x240 palette-index buffer. |
| `const uint16_t *cz_palette(void)` | The 15 RGB565 palette entries. |
| `int cz_dirty(void)` | 1 if the framebuffer changed since the last `cz_dirty` or `cz_dirty_rows` call. Renders first. |
| `int cz_dirty_rows(int *y0, int *y1)` | Like `cz_dirty`, and fills the inclusive row span touched since the last call. The firmware pushes only those rows. |
| `int cz_wants_sleep(void)` | 1 while the Sleep screen is showing. The host may deep sleep, then wake on touch and call `cz_init` with the blob. |
| `uint32_t cz_stat(int which)` | Monotonic counters since init: `CZ_STAT_FRAMES`, `CZ_STAT_PIXELS_FILLED`, `CZ_STAT_SPRITE_PIXELS`, `CZ_STAT_TEXT_GLYPHS`. |

### Brightness, clock, timezone

| Signature | What it does |
|---|---|
| `int cz_brightness(void)` | 100, 40 or 10. Chosen on the Settings wheel; the host drives the backlight from it. |
| `void cz_set_brightness(int pct)` | Accepts only 100, 40 or 10. Persisted in the save blob. |
| `void cz_set_clock(int minute_of_day)` | 0..1439 local minutes since midnight; -1 means unknown. Values of 1440 or more are ignored. Drives the day and night sky and the Clock row. Persisted. |
| `int cz_clock(void)` | Current local minute of day, advancing with ticks, or -1 when unknown. |
| `int cz_timezone(void)` | UTC offset in hours, default 8. |
| `void cz_set_timezone(int hours)` | -12..14, anything else ignored. Persisted. |

### Settings values fed by the host

| Signature | What it does |
|---|---|
| `void cz_set_version(const char *running)` | Up to 15 bytes, e.g. "1.1.0". Shown on the Update and About rows. |
| `void cz_set_update(const char *available)` | A newer version string, or "" or NULL for up to date. Changes what the Update row does when activated. |
| `void cz_set_wifi(const char *ssid, int state)` | SSID up to 32 bytes plus `CZ_WIFI_OFF`, `CZ_WIFI_CONNECTING`, `CZ_WIFI_OK` or `CZ_WIFI_FAIL`. Shown on the WiFi row. |
| `int cz_host_request(void)` | Pops one pending request: `CZ_REQ_PORTAL`, `CZ_REQ_CHECK_UPDATE`, `CZ_REQ_INSTALL_UPDATE`, `CZ_REQ_FACTORY_RESET`, `CZ_REQ_SYNC` or `CZ_REQ_WIFI_FORGET`, lowest first; `CZ_REQ_NONE` when empty. Nothing in the core raises `CZ_REQ_FACTORY_RESET` today. |
| `void cz_set_creatures(unsigned mask)` | Owned creatures from the server (bit per `enum cz_creature`; 0 is ignored). A gained bit plays Egg for the highest gained creature (after Hatch or Portal if one is showing); otherwise, if the shown creature is no longer owned, it switches to the lowest owned one at once. `cz_set_creature` also marks its creature owned. Saved in the blob. |
| `unsigned cz_creatures(void)` | The owned mask. |
| `void cz_set_wifi_list(const char *ssids)` | The host's saved networks, `\n`-separated, at most `CZ_WIFI_NETS` (5) of up to 32 bytes, listed on the WiFi screen. |
| `int cz_wifi_forget(void)` | After `CZ_REQ_WIFI_FORGET`: the index into the last list to forget, then -1. |
| `void cz_portal(const char *ap)` | Shows Portal for that access point name; "" or NULL leaves it to the base screen. |

### Introspection

| Signature | What it does |
|---|---|
| `int cz_screen(void)` | Current `enum cz_screen`. |
| `int cz_hearts(void)` | 0..4. |
| `int cz_creature(void)` | Current `enum cz_creature`. |
| `int cz_pose(void)` | The sprite pose the current screen shows, including the Home blink. |
| `uint32_t cz_hunger_ms(void)` | Milliseconds since the last feed, capped at 7 days. |

## State machine

Ten screens, `enum cz_screen`. Home and Sulk are the two resting screens; which one you land on is decided by `sulking()`: hearts at 1 or below, or 6 h since the last feed. Every other screen returns to that base screen when it is done.

```
                 prompt typed + 2 s hold
   HATCH ------------------------------------> HOME <----------> SULK
   (ignores touch,                              ^  (hearts <= 1 or 6 h unfed, re-evaluated every tick)
    message, check-in)                          |
                                                |  from HOME or SULK:
   tap ..................... FEED (3 s) --------+
   swipe, any direction .... PLAY (3 s) --------+
   hold 1 s ................ QR (30 s or tap) --+
   double tap .............. SETTINGS ----------+  (hold, double tap, Exit row, 20 s idle)
   30 s idle ............... SLEEP (tap) -------+
   cz_message() ............ TALK (8 s) --------+  from any screen except HATCH
   cz_checkin() ............ CHECKIN (4 s) -----+  from any screen except HATCH
```

| Screen | Enters when | Leaves when |
|---|---|---|
| `CZ_S_HATCH` | Fresh pet (no valid save blob). | The prompt has typed out at 60 ms per character and the 2 s rise has ended. Sets `hatched`. Taps, messages and check-ins are ignored here. |
| `CZ_S_HOME` | Base screen while not sulking. | Any gesture or event above; 30 s without touch goes to Sleep (never in portrait mode). |
| `CZ_S_SULK` | Base screen while sulking. Same gestures as Home. | A feed or play that lifts hearts above 1 and hunger under 6 h switches back to Home on the next tick. |
| `CZ_S_FEED` | Tap on Home or Sulk. +1 heart (max 4), hunger reset. | 3 s, or a tap. |
| `CZ_S_PLAY` | Swipe on Home or Sulk. +1 heart only if 30 min have passed since the last rewarded play. | 3 s, or a tap. |
| `CZ_S_TALK` | `cz_message()`. | 8 s, or a tap. |
| `CZ_S_QR` | Finger held still for 1 s on Home or Sulk. Fires while the finger is still down. | 30 s, or a tap. |
| `CZ_S_CHECKIN` | `cz_checkin()`. | 4 s, or a tap. |
| `CZ_S_SLEEP` | 30 s idle on Home or Sulk. `cz_wants_sleep()` is 1 here. | A tap. The host usually deep sleeps instead and re-inits on wake. |
| `CZ_S_SETTINGS` | Double tap on Home or Sulk (a first tap that fed the pet is undone). | Hold, double tap, the Exit row, or 20 s idle. |
| `CZ_S_EGG` | `cz_set_creatures` gains a creature. Wobble, crack, burst, then at 2.8 s the new creature with its default name. | 4 s. A tap before 2.8 s jumps to the reveal, after it ends Egg. Messages and check-ins are dropped; it never sleeps. |
| `CZ_S_WIFI` | Settings, WIFI row. Rows: each saved SSID, ADD NETWORK (raises `CZ_REQ_PORTAL`), BACK. A centre/right tap on an SSID arms TAP TO FORGET; a second one at least 400 ms later raises `CZ_REQ_WIFI_FORGET`. | BACK, hold or 20 s idle return to Settings on the WiFi row. |
| `CZ_S_PORTAL` | `cz_portal(ap)`: a QR of `WIFI:T:nopass;S:<ap>;;`, banner JOIN <ap> / 192.168.4.1. | Only `cz_portal("")`. Taps, messages and check-ins do nothing; it never sleeps. |

A tap on any event screen (Feed, Play, Talk, QR, Check-in, Sleep) dismisses it to the base screen. Talk and Check-in interrupt whatever is showing, Settings and Sleep included.

### Rendering

Nothing is drawn inside `cz_tick`. When the host calls `cz_framebuffer`, `cz_dirty` or `cz_dirty_rows`, the core packs everything the picture depends on into a 32-bit view key (screen, hearts, pose, animation step or Hatch progress, sky phase) and redraws only if the key differs from the last drawn one or a setter marked the state stale. When only the animation changed it clips the redraw to the screen's animation box from `cz_anim_box`; a Home blink clips to the pixels where the idle and blink sprites differ. The firmware then pushes only the dirty row span.

## Gestures

Detected in `cz_touch` from raw down, move and up events. Constants are in `citizen.c`.

| Gesture | Rule | On Home or Sulk | On Settings | Elsewhere |
|---|---|---|---|---|
| Tap | Up within 300 ms of down, moved less than 12 px | Feed | Wheel tap (see the Settings wheel) | Dismiss to base; nothing on Hatch |
| Double tap | A second tap within 400 ms of the first | Open Settings; a feed the first tap started is undone | Leave Settings; a value change the first tap started is dropped | Two plain taps |
| Swipe | Moved 40 px or more within 600 ms of down; horizontal when dx >= dy, vertical otherwise | Play, either direction | Horizontal: change the value (right forward, left back). Vertical: move the wheel (swipe up selects the next row) | Nothing |
| Hold | Finger down 1 s or more, moved less than 12 px; fires from `cz_tick` while still down | QR screen | Leave Settings | Nothing |

Once a swipe or hold has consumed the touch, the up event does nothing. Any touch resets the 30 s idle timer, including moves with no finger down, which the bench uses to keep the pet awake.

## Timers

All from `citizen.c` and `screens.c`. Timers are driven by the `now_ms` the host passes; `cz_init` applies `slept_seconds` on top.

| Timer | Value | Effect |
|---|---|---|
| Heart loss | 90 min unfed | Lose 1 heart per 90 min since the last feed, at most 4 (`lost` counts them so a feed resets cleanly). |
| Feed | immediate | +1 heart (max 4), hunger and `lost` reset to 0. |
| Play reward | once per 30 min | +1 heart (max 4). A heart earned by play rebases hunger to the start of its 90 min window so it lives a full window. Fresh pets can play at once. |
| Sulk | hearts <= 1 or 6 h unfed | Base screen becomes Sulk. |
| Age cap | 7 days | Hunger, play age and slept time are capped so the ms counters stay clear of uint32 overflow. |
| Idle sleep | 30 s | Home or Sulk goes to Sleep. Not in portrait mode. |
| Settings idle | 20 s | Settings returns to base. |
| Settings pending tap | 400 ms | A value tap waits this long so a double tap can cancel it. |
| Feed, Play | 3 s | Event screen duration. |
| Check-in | 4 s | Event screen duration. |
| Talk | 8 s | Event screen duration. |
| QR | 30 s | Screen timeout. |
| Hatch typing | 60 ms per character | Then a 2 s hold while the sprite eases up from row 188 to 100. |
| Home blink | 150 ms every 4 s | Pose flips to `CZ_BLINK`. |
| Breath | 600 ms per step | Home and Sulk bob through 0, 1, 2, 1 px. Sleep breathes at 1200 ms per step. |
| Bob | 250 ms per step | Feed, Play, Talk, Check-in, Sulk shiver. Talk cursor blinks at 500 ms. QR pet moves at 1200 ms. |
| Feed crumbs | 750 ms per crumb | 3, 2, 1, 0 crumbs over the 3 s. |
| Sulk drop | every 2 s | Sweat drop slides 4 steps down the head. |
| Clock | real time | Minute of day advances with ticks, wraps at midnight. Sky phase: night before 06:00 and from 20:00, dawn until 08:00, day until 17:30, then dusk. Unknown clock renders night. |

## Save blob

`cz_save` writes exactly `CZ_SAVE_SIZE` = 64 bytes. Multi-byte fields are little endian. The host stores it opaquely (the firmware keeps it in Preferences under `save`) and hands it back to `cz_init`.

| Offset | Size | Field |
|---|---|---|
| 0 | 2 | Magic `'C'`, `'Z'` |
| 2 | 1 | Version, 5. Version 2 blobs (pre-clock firmware) still restore with timezone 8 and clock unknown; versions 2-4 own only their creature. |
| 3 | 1 | Creature, 0..2 |
| 4 | 1 | Hearts, 0..4 |
| 5 | 1 | Hatched flag |
| 6 | 1 | Hearts lost since the last feed, 0..4 |
| 7 | 1 | Brightness, 100, 40 or 10 |
| 8 | 4 | Seconds since the last feed |
| 12 | 4 | Seconds since the last rewarded play |
| 16 | 11 | Name, NUL terminated, at most 10 characters (byte 26 is always 0) |
| 27 | 1 | Timezone + 12, so 0..26 |
| 28 | 4 | Seconds since local midnight, or `0xFFFFFFFF` when the clock is unknown |
| 32 | 1 | Chosen sky (v4) |
| 33 | 1 | Screen always on (v4) |
| 34 | 1 | Unlocked skies mask (v4) |
| 35 | 1 | Owned creatures mask (v5); must hold byte 3's bit |
| 36 | 24 | Zero |
| 60 | 4 | FNV-1a checksum of bytes 0..59 |

`restore` rejects a blob when the magic, version, checksum or any range check fails, and `cz_init` then hatches a fresh pet. The firmware reads the name straight out of bytes 16..26 because the core has no name getter.

## Build and test

Targets are in the top-level `Makefile`. The core compiles with `clang -std=c99 -Wall -Wextra -Werror -O1 -fno-common`; bench and soak use `-O2` because they measure speed (the firmware itself is built `-Os` by Arduino).

| Command | What it does |
|---|---|
| `make test` | Builds `tests/test_core` and runs it: flow, save and restore, every screen, telemetry, brightness, Settings, clock, QR geometry, dismiss, dither, Hatch rise, animation bounds, double tap undo. Writes every screen to `tests/out/*.ppm`. Ends with `all core tests passed`. |
| `make bench` | Per-screen cost table (below) and an ESP32-C3 estimate. |
| `make soak` | 7 simulated days of badge life: seeded random gestures at an event-day rate, chat messages, a check-in, an hourly save and init round trip, a nightly 8 h deep sleep. Every frame is range checked and redrawn to prove determinism. Ends with `SOAK PASSED`. |
| `make wasm` | Builds `sim/core.wasm` with Homebrew LLVM (`/opt/homebrew/opt/llvm/bin/clang`, `wasm-ld` from the `lld` formula), `-DCZ_FREESTANDING -DNDEBUG`, exporting every `cz_*` declared in `citizen.h`. |
| `make frames` | Renders the launch-film screen sequences from `video/render_frames.c`. |
| `scripts/check.sh` | Runs clean, test, soak, bench, wasm, then `pio run -e citizen` and fails if flash exceeds `FLASH_BUDGET` (default 1,700,000 bytes) or static RAM exceeds `RAM_BUDGET` (default 200,000 bytes), then the browser simulator's headless selftest. Run it before every push; CI runs the same. |

Last run, 16 Oct 2026: `make test` wrote 23 screens and passed. `make soak` ran 524,669 ticks and 347,157 frames in 26.26 s of wall time, with 1,166 gestures, 35 messages, 1 check-in, 112 hourly round trips and 7 deep sleeps, hearts between 0 and 4, every screen visited.

## Frame cost

`make bench` on 16 Oct 2026, native `-O2` on a Mac. Each row is the median of 5 runs of 2000 forced full redraws. `esp_est_ms` multiplies the native time by `CZ_SLOWDOWN` (default 120, a placeholder for a 160 MHz single-issue RISC-V against this Mac; override with the env var and replace it with the firmware's measured `frame_ms` once hardware exists). `push_ms` is the SPI cost of the dirty rows at 40 MHz plus 40 us per 8-row chunk. `fps` is capped at the 30 Hz the firmware runs at.

```
case           native_us   rows   push_ms esp_est_ms   total_ms    fps
hatch              4.490    240    24.240      0.539     24.779   30.0
home              11.340    240    24.240      1.361     25.601   30.0
feed              11.993    240    24.240      1.439     25.679   30.0
play              11.678    240    24.240      1.401     25.641   30.0
talk              13.219    240    24.240      1.586     25.826   30.0
qr                96.668    240    24.240     11.600     35.840   27.9
checkin           11.506    240    24.240      1.381     25.621   30.0
sulk              11.386    240    24.240      1.366     25.606   30.0
sleep             25.500    240    24.240      3.060     27.300   30.0
settings           2.350    240    24.240      0.282     24.522   30.0
home_blink         6.648    130    13.160      0.798     13.958   30.0
home_nochange      0.007      0     0.000      0.001      0.001   30.0
```

Two things to read from it: the SPI push of a full frame costs more than any screen's drawing, so the dirty-row clipping (`home_blink` pushes 130 rows, an idle Home pushes none) is what keeps the badge responsive; and QR is the one expensive screen because it re-encodes the code on every redraw.

## Portrait mode

`cz_set_portrait(1)` turns the core into a picture of the pet for the web page: it marks the pet hatched, sets 4 hearts, jumps to Home, and from then on draws Home without the hearts row or the action icons. Touch events are ignored, so nothing can feed, play or open Settings, and the 30 s idle timer never puts it to sleep. The breath animation, the name footer and the day and night sky still run, so the web portrait matches what the badge shows. `cz_set_portrait(0)` restores normal behaviour.

## Settings wheel

Opened by a double tap on Home or Sulk. A vertical wheel of eleven rows: the previous row in ink at y 48, the selected row and its value in gold at y 84 and 108, the next row at y 140, with triangles above and below. Rows in order: BRIGHTNESS, SCREEN, CLOCK, TIMEZONE, CITIZEN, SKY, WIFI, SYNC, UPDATE, ABOUT, EXIT. The wheel wraps.

Touch zones, from `settings_tap`:

| Touch | Effect |
|---|---|
| Tap above y 70 (top third) | Move up one row |
| Tap below y 125 (bottom third) | Move down one row |
| Tap on the selected row, x below 80 | Change the value back |
| Tap on the selected row, x 80 or more (centre or right) | Change the value forward, or activate the row |
| Horizontal swipe | Same as a value tap: right forward, left back |
| Vertical swipe | Swipe up selects the next row, swipe down the previous |
| Double tap | Leave; the first tap's value change is dropped |
| Hold 1 s | Leave |
| 20 s idle | Leave |

A value tap is held for 400 ms before it applies so a double tap can cancel it. Arrows on the value row show which directions are live: both for Brightness, Clock, Timezone and Citizen; right only for WiFi, Sync, Update and Exit; none for About.

| Row | Value shown | Back | Forward |
|---|---|---|---|
| BRIGHTNESS | 10, 40 or 100 | Dimmer, stops at 10 | Brighter, stops at 100 |
| CLOCK | HH:MM or `--:--` | Back 15 min (to the previous quarter hour) | Forward to the next quarter hour. Either sets the clock to known. |
| TIMEZONE | UTC+8 style | -1 h, floor -12 | +1 h, ceiling 14. The local clock moves with it. |
| CITIZEN | TENUK, KENYALANG or HARIMAU | Previous owned creature | Next owned creature. Changes the name to the default; with one owned it does not move. |
| WIFI | NOT SET, or the SSID plus OFF, CONNECTING, OK or FAIL | nothing | Opens the WiFi screen |
| SYNC | TAP TO SYNC, or SYNCING until the host next calls `cz_set_wifi` | nothing | Raises `CZ_REQ_SYNC` |
| UPDATE | V<running> then NEW <version> or UP TO DATE | nothing | Raises `CZ_REQ_CHECK_UPDATE`, or `CZ_REQ_INSTALL_UPDATE` once the host has reported a newer version |
| ABOUT | V<running> and the last path segment of the QR URL (the slug) | nothing | nothing |
| EXIT | | nothing | Leave Settings |

Changes to brightness, clock, timezone and creature apply immediately in the core; the firmware watches `cz_brightness`, `cz_timezone` and `cz_creature` each loop and persists what changed.
